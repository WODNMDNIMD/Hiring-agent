# RecruitFlow AI Demo 流程说明

本文档用于说明 RecruitFlow AI Demo 的完整展示流程，适合放入项目仓库作为提交材料的一部分。内容重点是业务流程、页面功能和 Demo 操作顺序，不包含录屏旁白。

## 1. Demo 目标

RecruitFlow AI 面向 HR 招聘流程中的重复录入、状态跟踪和数据同步问题，提供一个轻量可运行的 AI 应用 Demo。

系统展示的核心能力是：

- 自动解析简历，提取候选人关键字段；
- 根据岗位 JD 生成匹配点、风险点和标准化推荐语；
- HR 确认后创建候选人记录和申请记录；
- 将候选人推荐摘要推送到企业微信群；
- 解析面试官反馈并更新候选人流程状态；
- 将数据同步到腾讯文档 Mock 表；
- 通过候选人台账、招聘看板和事件日志完成复盘。

## 2. 核心流程

```text
岗位配置
  ↓
简历进入
  ↓
AI解析候选人字段 + JD匹配 + 推荐语
  ↓
HR确认入库
  ↓
企业微信群推送 + 腾讯文档Mock同步
  ↓
面试官反馈解析
  ↓
状态机校验 + HR确认更新
  ↓
候选人台账 + 招聘看板 + 事件日志
```

## 3. 演示环境

默认运行模式：

```text
AI_PROVIDER=mock
TENCENT_DOCS_MODE=mock
WECOM_NOTIFY_ENABLED=false
```

默认 Mock 模式不依赖真实模型 Key、企业微信 Webhook 或腾讯文档授权，可以保证面试现场稳定运行。

启动命令：

```powershell
.\.venv\Scripts\activate
streamlit run app.py
```

访问地址：

```text
http://localhost:8501
```

## 4. 页面说明

### 4.1 岗位配置

用途：维护招聘岗位和岗位 JD。

展示内容：

- 岗位名称；
- 招聘负责人；
- 岗位 JD；
- 已创建岗位列表。

业务意义：

岗位 JD 是 AI 判断候选人匹配点、风险点和推荐程度的依据。Demo 默认提供 `AI产品经理` 岗位，也支持手动新增岗位。

### 4.2 AI候选人录入

用途：完成简历进入后的 AI 解析、岗位匹配和推荐语生成。

支持方式：

- 上传 PDF / DOCX / TXT 简历；
- 直接粘贴简历文本；
- 使用系统默认示例简历。

展示内容：

- 候选人姓名；
- 联系方式；
- 学历；
- 工作年限；
- 技能关键词；
- 期望薪资；
- 匹配分；
- 匹配点；
- 风险点；
- 标准化推荐语。

业务意义：

HR 不需要手工从简历中复制字段，系统可以自动提取候选人信息，并根据岗位 JD 生成一段面试官可阅读的推荐摘要。

确认动作：

```text
确认入库并推送面试官群
```

确认后系统会：

- 创建或更新候选人记录；
- 创建岗位申请记录；
- 写入招聘事件日志；
- 触发企业微信群推送；
- 触发腾讯文档 Mock 同步。

### 4.3 企业微信群

用途：配置和测试企业微信群机器人推送。

展示内容：

- 当前连接模式；
- Webhook 是否填写；
- 消息格式；
- 测试消息内容；
- Payload 预览；
- 测试发送结果。

业务意义：

真实部署时，候选人推荐摘要可以通过企业微信群机器人推送到面试官群。Demo 默认使用 Mock 模式，系统会生成企业微信消息 Payload 并写入外部集成日志。

说明：

普通企业微信群机器人适合作为消息推送出口，不适合直接监听群内全部消息。群内反馈在当前 Demo 中通过 `面试官反馈` 页面粘贴解析，后续可升级为企业微信自建应用回调。

### 4.4 面试官反馈

用途：解析面试官群反馈，并驱动候选人状态更新。

示例反馈：

```text
李明可以约面，建议安排下周二下午，重点考察项目推进能力。
```

展示内容：

- 候选申请；
- 当前阶段；
- 面试官反馈文本；
- AI 识别的动作意图；
- 下一流程状态；
- 置信度；
- 候选人邀约话术。

业务意义：

面试官在群里回复“可以约面”“不合适”“进入复试”“发Offer”等内容后，系统可以把自然语言反馈转化为结构化招聘事件。

确认动作：

```text
确认更新流程状态
```

确认后系统会：

- 校验状态流转是否合法；
- 更新申请阶段；
- 写入反馈确认事件；
- 同步腾讯文档 Mock 表。

### 4.5 候选人台账

用途：展示自动维护的候选人招聘台账。

展示内容：

- 候选人；
- 岗位；
- 当前阶段；
- 匹配分；
- AI 建议；
- 负责人；
- 学历；
- 学校；
- 工作年限；
- 期望薪资；
- 更新时间。

支持操作：

- 按阶段筛选；
- 按岗位筛选；
- 按负责人筛选；
- 关键词搜索；
- 匹配分筛选；
- 导出 CSV。

业务意义：

该页面替代 HR 手工维护在线表格的工作。候选人入库和状态更新后，台账会自动刷新。

### 4.6 招聘看板

用途：展示招聘流程的实时统计和复盘视图。

展示内容：

- 候选人总数；
- 活跃流程数量；
- 待反馈数量；
- 平均匹配分；
- 招聘阶段漏斗；
- 岗位候选人分布；
- 负责人负载；
- 最近推进记录。

业务意义：

管理者可以实时查看招聘进度，不需要等待 HR 每日手工汇总。

### 4.7 事件日志

用途：展示系统关键动作和外部集成记录。

展示内容：

- 招聘事件；
- 腾讯文档 Mock 文件；
- 外部集成日志。

业务意义：

事件日志保证 AI 参与招聘流程后，每一步都有记录。即使 AI 识别结果需要调整，也可以通过日志进行审计、排查和回溯。

## 5. 推荐演示顺序

建议按照以下顺序展示：

1. `岗位配置`：说明岗位 JD 是 AI 匹配依据；
2. `AI候选人录入`：展示简历解析、匹配分析和推荐语；
3. `企业微信群`：展示推送配置和 Mock 模式；
4. `面试官反馈`：展示反馈解析和状态更新；
5. `候选人台账`：展示自动生成的候选人记录；
6. `招聘看板`：展示数据可视化；
7. `事件日志`：展示可追溯和同步记录。

## 7. Demo 亮点

- 聚焦真实 HR 工作流，不是孤立聊天机器人；
- 简历解析、推荐语、反馈解析均体现 AI 实际应用；
- HR 确认后才写入核心数据，降低 AI 误判风险；
- 状态机校验保证流程可控；
- 企业微信和腾讯文档采用适配器设计，便于后续接入真实 API；
- Mock 模式保证无外部授权也能完整演示；
- 事件日志保证流程可追溯。
